## 1. Addressing, Topology, and Environment Architecture

### 1.1 Addressing Modes in oneM2M and ACME CSE

oneM2M specifies three distinct URI addressing formats to locate resources in a distributed service mesh:

| Addressing Mode | Format Template | Automotive SDV Concrete Example | Standard ETSI IN-CSE Example | Description |
| :--- | :--- | :--- | :--- | :--- |
| **SP-Relative (Structured)** | `/<cse_id>/<cse_rn>/<ae_rn>/<cnt_rn>` | `/id-sdv/sdv-cse/AE_CabinNode_Car01/cnt_raw_telemetry` | `/id-in/cse-in/vehicle-001/raw-telemetry` | Prefixed by CSE-ID (`/id-sdv` or `/id-in`) and full resource hierarchy path. |
| **CSE-Relative (Structured)** | `/<cse_rn>/<ae_rn>/<cnt_rn>` | `/sdv-cse/AE_CabinNode_Car01/cnt_raw_telemetry` | `/cse-in/vehicle-001/raw-telemetry` | Relative to the local hosting CSEBase (`sdv-cse` or `cse-in`). |
| **SP-Relative (Unstructured)** | `/<cse_id>/<resource_id>` | `/id-sdv/cin_1729000000_123` | `/id-in/cin_1729000000_123` | Direct O(1) access by persistent unique `ri` regardless of tree depth. |
| **CSE-Relative (Unstructured)** | `/<resource_id>` | `/cin_1729000000_123` | `/cin_1729000000_123` | Unstructured reference within local CSE database. |
| **Absolute URI** | `//<sp_id>/<cse_id>/<cse_rn>/...` | `//acme.example.com/id-sdv/sdv-cse` | `//acme.example.com/id-in/cse-in` | Globally unique across multiple Service Provider M2M domains. |

> [!IMPORTANT]
> **Trailing Slash Gotcha:** ACME CSE is strictly sensitive to trailing slashes on root resources:
> - `http://localhost:8080/sdv-cse` &rarr; **HTTP 200 OK** (Returns `<m2m:cb>`)
> - `http://localhost:8080/sdv-cse/` &rarr; **HTTP 400 Bad Request** (`invalid arguments/attributes`)

## 2. oneM2M Entity Roles and Topology Classification

oneM2M classifies functional nodes according to their capability to host CSE and AE layers:

```
                  +----------------------------------------------+
                  |         IN-CSE (Infrastructure Node)         |
                  |     Hosted on Cloud / Edge Core Gateway      |
                  |  Root: /sdv-cse (cseID: /id-sdv, cseType: 1) |
                  +----------------------+-----------------------+
                                         |
                       Mcc / Mca         |         Mca (MQTT TS-0010)
                    (HTTP / CoAP)        |         (Port 1883 / 8883)
                                         |
         +-------------------------------+-------------------------------+
         |                                                               |
+--------v----------------------+                       +----------------v--------+
|    MN-CSE (Middle Node)       |                       |   ADN-AE (Application   |
|   Edge Gateway Aggregator     |                       |     Dedicated Node)     |
| (cseType: 2, e.g. Zone ECU)   |                       |  ESP32-S3 Microcontroller
+-------------------------------+                       | (Origin: C_CabinNode_Car01)
         |                                              +-------------------------+
         | Mca
+--------v----------------------+
|   ASN-AE / ASN-CSE (Sensor)   |
| Low-power cabin sensor node   |
+-------------------------------+
```

* **IN-CSE (Infrastructure Node CSE, `cseType = 1`):** The central authority hosting the complete semantic resource tree. In this project, `sdv-cse` operates as an IN-CSE on the Raspberry Pi 5 gateway.
* **MN-CSE (Middle Node CSE, `cseType = 2`):** Sits between field sensors and the cloud/gateway, providing local caching and actuation interlocks.
* **ASN-CSE (Application Service Node CSE, `cseType = 3`):** Autonomous node containing at least one AE and a subordinate CSE layer.
* **ADN-AE (Application Dedicated Node AE):** Lightweight endpoint hosting strictly an Application Entity without a local CSE stack (e.g. the ESP32-S3 microcontroller running FreeRTOS).

## 5. System Internal Resources & UI Anomalies Deep Dive

In a fresh, vanilla IN-CSE deployment, ACME automatically instantiates built-in infrastructure resources under the root CSEBase. These are **not Application Entities**:

```
/sdv-cse (ty=5, CSEBase)
├── acpCreateRootResources (ty=1, <m2m:acp> - Bootstrap access policy)
├── acpRetrieveCSEBase     (ty=1, <m2m:acp> - Public CSEBase inspection policy)
├── CAdmin                 (ty=2, <m2m:ae>  - Administrative super-user originator)
├── defaultNTP             (ty=26, <m2m:ntp> - Core clock synchronization policy)
└── AEContactList          (ty=43, <m2m:alst> - oneM2M AE contact routing registry)
```

### The `unknown: AEContactList` Phenomenon
* **Why does the ACME Web UI display `unknown: AEContactList`?**
  ACME's Web UI presentation layer relies on an internal lookup dictionary (`resourceTypeDetails`) to format the resource badge. In current ACME releases, the UI dictionary entry for `ty=43` (`ALST`) is unpopulated in the browser template, triggering a fallback string: `unknown: <resourceName>`.
* **Protocol Reality:** At the oneM2M protocol engine, database, and REST interface layers, `AEContactList` is 100% compliant with **ETSI TS 118 101 Rel 4 (`ty=43`, short code `m2m:alst`)**.
* **Discovery Filtering:** All standard vehicular queries explicitly filter on `ty=2` (`GET /sdv-cse?fu=1&ty=2`), which cleanly isolates vehicle AEs and ignores `AEContactList`.

## 6. Protocol Control Headers & Originator Semantics

Every HTTP request to ACME oneM2M CSE **must** include standard control headers:

```http
X-M2M-Origin: CAdmin
X-M2M-RI: req_1729000000_101
X-M2M-RVI: 3
Accept: application/json
Content-Type: application/json;ty=4
```

| Header | Full Name | Standard Rules | Allowed Values in Project |
| :--- | :--- | :--- | :--- |
| **`X-M2M-Origin`** | Originator Credential | Identifies caller identity for Access Control Policy (`acp`) evaluation. | `CAdmin` (Admin super-user), `C_vehicle_nodes` (Fleet wildcard), `C_CabinNode_Car01` (Single vehicle node). |
| **`X-M2M-RI`** | Request Identifier | **Mandatory** on every request. Must be unique per request to correlate responses. | `req_<unix_timestamp>_<random>` or alphanumeric string. |
| **`X-M2M-RVI`** | Release Version Indicator | Declares oneM2M release conformance of the requesting entity. | `"2a"`, `"3"`, `"4"`, `"5"`. ACME srv pool supports Releases 2a through 5. |
| **`Content-Type`** | Serialization & Resource Type | Mandatory on `POST` requests. Must specify target resource type `ty` via parameter! | `application/json;ty=<int>` on CREATE (`POST`).<br>`application/json` on UPDATE (`PUT`). |
| **`Accept`** | Content Negotiation | Declares expected response serialization. | `application/json`, `application/vnd.onem2m-res+json`, `application/cbor`. |

## 7. Discovery, Filter Usage (`fu`), and Result Content (`rcn`)

### 7.1 Filter Usage (`fu`)
Query parameter defining how the CSE processes discovery criteria:
* **`fu=1` (Discovery Mode):** Returns a flat list of matching resource URI references wrapped in `{"m2m:uril": [...]}`. Fast and lightweight.
* **`fu=2` (Conditional Retrieval Mode):** Returns full representations of matching resources wrapped in a list.

### 7.2 Result Content (`rcn`) Options
The `rcn` query parameter dictates what resource information is returned in the response payload:

| `rcn` | Mode Name | Behavior | Use Case |
| :---: | :--- | :--- | :--- |
| **0** | `nothing` | Returns an empty body with HTTP status & headers. | Low-bandwidth telemetry confirmation. |
| **1** | `attributes` | **(Default)** Returns only the target resource's direct attributes. | Standard entity introspection. |
| **2** | `hierarchical-address` | Returns hierarchical structured path (`rn`-based). | Path validation. |
| **3** | `hierarchical-and-attr` | Combines hierarchical path and attributes. | Topology audit. |
| **4** | `attributes-and-children` | **Deep Tree Inspection.** Recursively dumps the resource and all descendant sub-trees! | Full vehicle manifest verification & UI workbench tree rendering. |
| **5** | `attributes-and-child-refs`| Returns attributes and URI references to immediate child resources. | Paginated navigation. |
| **6** | `child-refs-only` | Returns list of child URI references only. | Container enumeration. |
| **8** | `child-resources-only` | Returns representations of immediate children without parent attributes. | Batch telemetry retrieval. |

### 8.1 CREATE (`POST`) Operations

#### C1: Register Vehicle Application Entity (`<m2m:ae>`, `ty=2`)
```bash

  -H "X-M2M-Origin: C_CabinNode_Car01" \
  -H "X-M2M-RI: req_ae_001" \
  -H "X-M2M-RVI: 3" \
  -H "Content-Type: application/json;ty=2" \
  -H "Accept: application/json" \
  -d '{
    "m2m:ae": {
      "rn": "AE_CabinNode_Car01",
      "api": "N.org.fhtw.sdv.cabin",
      "rr": true,
      "srv": ["2a", "3", "4"],
      "poa": ["mqtt://mosquitto:1883/pdu/sdv-cse/AE_CabinNode_Car01"],
      "lbl": ["vehicle", "sdv-fleet", "identity:VIN-WAUZZZ-SDV-2026-0001"]
    }
  }'
```

```bash
  -H "X-M2M-RVI: 3" \
  -H "Content-Type: application/json;ty=3" \

    "m2m:cnt": {
      "rn": "cnt_raw_telemetry",
      "mni": 1000,
      "mbs": 1048576,
      "mia": 86400,
      "lbl": ["sensor", "scd30", "dht22", "raw-telemetry"]
    }
  }'
```
* **Expected Response:** `HTTP 201 Created` / `X-M2M-RSC: 2001`

#### C3: Ingest Telemetry ContentInstance (`<m2m:cin>`, `ty=4`)

## 9. Downlink Notification Routing & Subscriptions

### 9.1 Subscription Trigger Parameters (`net` and `nct`)

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        NOTIFICATION EVENT TYPES (net)                  │
├───────┬────────────────────────────────────────────────────────────────┤
│ Value │ Trigger Event Condition                                        │
├───────┼────────────────────────────────────────────────────────────────┤
│ [1]   │ Update of direct target resource attributes                    │
│ [2]   │ Deletion of direct target resource                             │
│ [3]   │ Creation of child resource (STANDARD: new <cin> in <cnt>)      │
│ [4]   │ Deletion of child resource                                     │
└───────┴────────────────────────────────────────────────────────────────┘
```

```text
┌────────────────────────────────────────────────────────────────────────┐
│                       NOTIFICATION CONTENT TYPES (nct)                 │
├───────┬────────────────────────────────────────────────────────────────┤
│ Value │ Dispatched Webhook Payload Structure                           │
├───────┼────────────────────────────────────────────────────────────────┤
│ 1     │ Complete representation of modified/created resource           │
│ 2     │ Modified attributes delta only                                 │
│ 3     │ Resource ID reference string only                              │
└───────┴────────────────────────────────────────────────────────────────┘
```

### 9.2 Downlink Transport Destinations (`nu` and `downlink_notification_url`)
The Notification URI (`nu`) array supports multi-protocol dispatch:
* **HTTP Microservice Webhook (`downlink_notification_url`):** `["http://192.168.122.91:8080/downlink"]` or `["http://bridge_ae:5000/notification"]` (Dispatches standard `m2m:sgn` POST).
* **Native TS-0010 MQTT Topic:** `["mqtt://mosquitto:1883/pdu/sdv-cse/AE_CabinNode_Car01/commands?ct=json"]` (Publishes downlink directive directly to broker topic without intermediary).

## 10. oneM2M Response Status Codes (RSC) Quick Reference

ACME transmits the official 4-digit oneM2M status code via the `X-M2M-RSC` header:

| RSC | Class | Description | Standard HTTP Status |
| :---: | :--- | :--- | :--- :--- |
| **`2000`** | Success | **OK** &bull; Successful retrieval or update. | 200 OK |
| **`2001`** | Success | **CREATED** &bull; New resource instantiated. | 201 Created |
| **`2002`** | Success | **DELETED** &bull; Resource purged from CSE tree. | 200 OK |
| **`2004`** | Success | **UPDATED** &bull; Target resource modified. | 200 OK |
| **`4000`** | Client Error | **BAD_REQUEST** &bull; Syntax failure or missing mandatory attribute. | 400 Bad Request |
| **`4004`** | Client Error | **NOT_FOUND** &bull; Target URI does not resolve in CSE hierarchy. | 404 Not Found |
| **`4103`** | Client Error | **TARGET_NOT_SUBSCRIBABLE** &bull; Attempt to attach `<sub` to invalid parent. | 403 Forbidden |
| **`4105`** | Client Error | **CONFLICT / ALREADY_EXISTS** &bull; Duplicate `rn` under same parent. | 409 Conflict |
| **`4107`** | Client Error | **RELEASE_VERSION_NOT_SUPPORTED** &bull; Declared `RVI` unsupported. | 400 Bad Request |
| **`5000`** | Server Error | **INTERNAL_SERVER_ERROR** &bull; CSE database or runtime failure. | 500 Server Error |
| **`5106`** | Server Error | **ORIGINATOR_HAS_NO_PRIVILEGE** &bull; ACP `pv`/`pvs` rejected caller. | 403 Forbidden |
